Publish playwright-direct: expose real-browser CDP to Playwright

Chrome 136+ ignores --remote-debugging-port when paired with the default
user-data directory, so attaching Playwright to an already-signed-in browser
stopped working. This plugin keeps the companion-extension approach (the
extension holds the debugger permission, so no relaunch or re-login is needed)
but rebuilds the CDP bridging so an external Playwright client can attach.

Bridge fixes over upstream dsh-doyourweb:

- Answer Schema.getDomains and Target.getBrowserContexts locally. Chrome
  rejects both on a page-level debugger session, which aborted Playwright's
  connectOverCDP handshake with a socket hang up.
- Emit Target.attachedToTarget from Target.attachToTarget. Playwright creates
  its Page object from that event, not from the command reply, so without it
  connectOverCDP succeeded but reported zero pages.
- Drop the internal Playwright self-connection. The relay is now driven by the
  external client, which removes the race where the relay was half-built and
  rejected the outside session.
- Let an external session and the plugin coexist, and stop tearing the relay
  down when only the external client disconnects.
- Create the relay on demand for /cdp/direct and /cdp/tab/<id>, so a tab can be
  attached without any DSH tool having touched it first.
- Add GET /cdp/info (ready CDP paths), GET /tabs (tabs the extension reports)
  and POST /cdp/api (one CDP command) for scripted use.

Also carried over from the working branch:

- Fall back when crypto.randomUUID is missing. It only exists in secure
  contexts, so serving the UI over plain HTTP on a LAN address crashed the
  whole client entry and surfaced as "Failed to load plugins".
- browser_act: upload action for file inputs, offset/nextOffset pagination on
  extract, a 5000 row cap, a getText action for whole-page text, and press
  without a ref for global shortcuts.
- Configurable exposeCdp, cdpAuthRequired and allowedTools.

Renamed to playwright-direct and reduced to the CDP path plus browser_open;
WebMCP, annotations, desktop app control and the other tools are no longer
registered by default.
